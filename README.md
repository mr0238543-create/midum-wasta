# ميدوم والواسطي

دليل محلي لأهالي مركزي ميدوم والواسطى: أنشطة، وظائف، تقييمات، محادثات، وطلبات خدمة.
الواجهة: React + Vite (عربي RTL). الخلفية: Supabase (Postgres + RLS + Auth + Storage + Realtime).

## ما الذي تحتاجه (حسابات خارجية)

| الحاجة | لماذا | ملاحظة |
|---|---|---|
| مشروع Supabase | قاعدة البيانات والدخول والصور | الخطة المجانية تكفي للبداية |
| (اختياري) Google Cloud OAuth | زر الدخول بواسطة Google | مجاني. راجع الخطوة ٣ |
| استضافة ثابتة (Netlify / Vercel / Cloudflare Pages) | نشر الواجهة | أي استضافة ملفات ثابتة |

## الإعداد خطوة بخطوة

1. **أنشئ مشروع Supabase** من supabase.com.
2. **شغّل ملفات قاعدة البيانات** من SQL Editor بالترتيب:
   1. `supabase/migrations/20261015000000_init.sql`
   2. `supabase/migrations/20261015000100_account_deletion.sql`
   3. `supabase/migrations/20261017000000_products.sql` (كتالوج المنتجات)
   4. `supabase/migrations/20261018000000_orders.sql` (الطلبات وطرق الدفع وإيصالات التحويل)
   5. `supabase/seed.sql` (الأقسام والقرى)
   - أسماء القرى في `seed.sql` مبدئية؛ راجعها وعدّلها من لوحة المشرف (تبويب «القرى») بعد أول دخول.
3. **فعّل الدخول**: Authentication ← Providers:
   - **Email**: مفعّل افتراضيًا. للتجربة السريعة أوقف «Confirm email»، وللإطلاق الحقيقي اتركه مفعّلًا.
   - **Google** (اختياري): أنشئ OAuth Client (نوع Web) من Google Cloud Console، وضع في «Authorized redirect URIs» الرابط الظاهر في صفحة Google داخل Supabase (`https://<project>.supabase.co/auth/v1/callback`)، ثم الصق Client ID وSecret في Supabase وفعّله.
   - Authentication ← URL Configuration: ضع رابط موقعك في Site URL وفي Redirect URLs.
4. **المتغيرات**: انسخ `.env.example` إلى `.env.local` واملأ:
   - `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` (مفتاح **anon** العام فقط. لا تضع `service_role` في الواجهة أبدًا).
   - `VITE_CONTACT_EMAIL`: بريد حقيقي تراقبه (يظهر في الخصوصية والشروط).
5. **أول مشرف**: سجّل الدخول مرة بالتطبيق برقمك، ثم نفّذ في SQL Editor:
   ```sql
   update profiles set role = 'admin' where phone = '2010XXXXXXXX';
   ```
   (اكتب الرقم بالصيغة المخزّنة فعليًا؛ راجعها أولًا بـ `select phone from profiles;` لأن Supabase قد يخزّنه بدون علامة `+`.) بعدها تظهر «لوحة المشرف» في حسابك.
6. **تخزين الصور**: ينشئ ملف الـ migration الحاوية `business-photos` وسياساتها تلقائيًا. تأكد من ظهورها في Storage.
7. **التشغيل محليًا**:
   ```bash
   npm install
   npm run dev
   ```
8. **النشر**:
   ```bash
   npm run build      # الناتج في dist/
   ```
   ارفع `dist/` للاستضافة وأضف المتغيرات نفسها في إعدادات الاستضافة. أضف رابط الموقع في Supabase ← Authentication ← URL Configuration.
   التطبيق يستخدم روابط `#/` فلا يحتاج إعادة توجيه خاصة.
9. **تطبيق جوال (اختياري)**: يمكن تغليف `dist/` بـ Capacitor. لم يُجرَّب.

## ما الذي يفعله التطبيق

- زائر: تصفح، بحث (عربي مع تطبيع الهمزات والتاء المربوطة)، فلتر القسم/القرية/التقييم، ترتيب بالأقرب/الأعلى/الأحدث، صفحة النشاط (اتصال، خرائط، مشاركة).
- مستخدم (بعد OTP): مفضلة، تقييم واحد لكل نشاط، محادثة، طلب خدمة وتتبعه، بلاغ، وظائف.
- صاحب نشاط: تسجيل نشاط بنفسه («قيد المراجعة»)، تعديل وإعادة إرسال بعد طلب تعديل، استقبال الطلبات والرد عليها.
- مشرف: اعتماد/رفض/طلب تعديل/إيقاف بسبب إلزامي (يصل لصاحب النشاط إشعارًا)، معالجة البلاغات، إدارة الأقسام والقرى، مراجعة الوظائف، حظر مستخدم.
- حذف الحساب نهائيًا من «حسابي» (يُمنع إن كنت المشرف الوحيد).
- الأمان على مستوى القاعدة: RLS، صلاحيات أعمدة، إخفاء الهاتف/العنوان وفق إعداد صاحب النشاط، حدود معدّل الإرسال، التحقق من حالة النشاط عبر triggers.

## ما الذي اختُبر فعلًا وما الذي لم يُختبر

**اختُبر:**
- **قاعدة البيانات على Postgres 16 حقيقي** (مع طبقة محاكاة لـ `auth` و`storage`): `npm run test:db` ← «ALL SECURITY TESTS PASSED». يغطي سياسات RLS، منع التصعيد إلى مشرف، إخفاء الحقول، الحالات المسموحة للنشاط والطلب، حدود المعدل، البلاغات، حذف الحساب.
- **الواجهة في Chromium (Playwright) على واجهة بيانات وهمية في الذاكرة** (`tests/ui`): ١٨ خطوة، نجحت كلها ٣ مرات متتالية: الرئيسية، حماية الصفحات، الدخول (رقم خاطئ/فشل SMS/رمز خاطئ/نجاح)، إضافة نشاط، مراجعة المشرف، البحث العربي، التقييم والمفضلة والطلب والمحادثة والبلاغ، الإيقاف، الوظائف، الأقسام، الحساب، الحذف، وغياب أخطاء console.
  ```bash
  cd tests/ui && node build.mjs && node e2e.mjs   # يحتاج esbuild وplaywright
  ```

**لم يُختبر (لا يمكن من بيئة التطوير هذه):**
- التشغيل مقابل **مشروع Supabase حقيقي** (ربط `src/api.js` بالخدمة الفعلية). اختُبر الجزء الخاص بقاعدة البيانات فقط، لكن استدعاءات `supabase-js` نفسها لم تُجرَّب.
- **الدخول بالبريد وGoogle** على Supabase الحقيقي (اختبارات `e2e.mjs` و`mock-api.js` ما زالت تحاكي الدخول القديم بالهاتف وتحتاج تحديثًا)، وحدود المعدل في Supabase Auth.
- **Cloudflare Turnstile**.
- **Realtime الفعلي** للمحادثات (اختُبر السلوك على محاكاة).
- **رفع الصور الفعلي** إلى Storage. ضغط الصور والتحقق من النوع والحجم اختُبرا في المتصفح فقط.
- أداء الواجهة على أجهزة حقيقية وشبكات بطيئة، وتطبيق الجوال.
- خريطة OSM تعتمد على الإنترنت (الإطار فارغ في بيئة الاختبار المعزولة).

لذلك أوصي بتجربة شاملة على مشروع Supabase تجريبي برقم اختبار قبل الإطلاق: تسجيل، إضافة نشاط بصورة، اعتماده كمشرف، تقييم من حساب ثانٍ، محادثة بين جهازين.

## حدود معروفة

- حذف نشاط أو حساب يحذف صور الحساب، لكن قد تبقى ملفات يتيمة إن فشل الحذف من Storage؛ يمكن تنظيفها من لوحة Supabase.
- «الأقرب» يعتمد على إحداثيات النشاط وموقع المستخدم (إن سمح به).
- نص الشروط والخصوصية قالب عام مناسب كبداية، **ويحتاج مراجعة قانونية** قبل الاستخدام التجاري.

## هيكل المشروع

```
src/            واجهة React (screens/ لكل شاشة، api.js طبقة البيانات الوحيدة)
supabase/       migrations + seed + tests (اختبارات الأمان على Postgres)
tests/ui/       اختبار المتصفح (Playwright) مع واجهة بيانات وهمية
```
